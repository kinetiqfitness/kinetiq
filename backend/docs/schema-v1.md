# Database schema v1 (draft)

Status: draft for review, all 5 tables written.
IDs are uuid. Times are timestamptz (UTC).

Hierarchy: user -> sessions -> sets -> reps -> fault_events

## users
| column | type | notes |
|---|---|---|
| id | uuid | PK. Same id as the Supabase Auth user. No passwords stored here. |
| display_name | text | shown in the app |
| created_at | timestamptz | default now() |

## sessions
One gym visit. Can contain several sets with different exercises.

| column | type | notes |
|---|---|---|
| id | uuid | PK, generated by the phone (works offline, safe to retry upload) |
| user_id | uuid | FK -> users.id, required |
| started_at | timestamptz | |
| ended_at | timestamptz | null until the session is finished |
| created_at | timestamptz | when the server received it |

## sets
One group of reps of a single exercise inside a session.

| column | type | notes |
|---|---|---|
| id | uuid | PK, generated by the phone |
| session_id | uuid | FK -> sessions.id, required |
| exercise | text | squat, overhead_press (deadlift later, if Block 2 lands on time) |
| set_number | integer | order inside the session, starting at 1 |
| started_at | timestamptz | |
| ended_at | timestamptz | |
| keypoints_path | text | path of the gzipped keypoint file in object storage. Null until the file is uploaded. We store the path, not a signed URL, because signed URLs expire. |
| created_at | timestamptz | when the server received it |

Rule: keypoints are never stored as rows. 33 landmarks x 15 fps x 40 s is about 19,800 rows per set.

## reps
One repetition inside a set. Small, read constantly by the dashboard.

| column | type | notes |
|---|---|---|
| id | uuid | PK, generated by the phone |
| set_id | uuid | FK -> sets.id, required |
| rep_number | integer | order inside the set, starting at 1 |
| start_ms | integer | start of the rep, ms from the start of the set (used by replay to seek in the keypoint file) |
| end_ms | integer | end of the rep, same reference |
| time_down_ms | integer | descending phase duration |
| time_up_ms | integer | ascending phase duration |
| depth_value | numeric | null if the exercise has no depth. Definition and unit: TBC with CV lead and math engineer |
| score | smallint | 0 to 100, CHECK (score BETWEEN 0 AND 100) |

Constraint: UNIQUE (set_id, rep_number), so a retried upload cannot create duplicate reps.

## fault_events
One row per detected fault per rep. Small and read constantly by the dashboard.

| column | type | notes |
|---|---|---|
| id | uuid | PK |
| rep_id | uuid | FK -> reps.id, required |
| fault_type | text | squat: shallow_depth, knee_valgus, forward_lean. Names TBC with CV lead. Validated in the API, not a Postgres enum, so new exercises don't need a heavy migration. |
| severity | numeric | 0 to 1, CHECK (severity BETWEEN 0 AND 1) |
| worst_ms | integer | moment of the worst frame, ms from the start of the set (same reference as reps.start_ms) |

Constraint: UNIQUE (rep_id, fault_type).

## Relations
users 1 -> N sessions 1 -> N sets 1 -> N reps 1 -> N fault_events
